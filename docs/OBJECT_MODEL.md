# DEX//PULSE Object Model

## Core grammar

`PulseObject -> Reflex -> optional PulseTarget -> PulseResult`

Every stage is typed, provenance-aware, and independently inspectable.

## Base PulseObject

Required fields:

```text
id                 ephemeral stable ID for the interaction
objectType         stable semantic type identifier
source             selection | pointerAX | focusedAX | frontmost | clipboard | result | spool | pin
createdAt
confidence         deterministic sources generally 1.0; inferred refinements lower
provenance         application/bundle/window/AX/file/reference metadata
privacyClass       public | ordinary | sensitive | secure-blocked
payloadDescriptor  summary/metadata, not necessarily persisted payload
```

Do not force every object into a text representation.

### Privacy and payload rules

`privacyClass` is enforced, not decorative:

- `public` — explicitly public material;
- `ordinary` — normal local user content; default for selected text/files;
- `sensitive` — likely secrets/private identifiers or user-marked sensitive; remote/cloud Targets are excluded unless explicitly overridden for that action;
- `secure-blocked` — password/secure-field material; value is never captured into a normal object.

Classifiers may increase sensitivity but must not silently downgrade it. Witness/habit stores receive metadata only unless a separate explicit persistence decision permits payload storage.

### Lifetime

Objects backed by live Accessibility references, PIDs, windows, or transient selections carry a context generation/token. Before execution the capability revalidates that the target still represents the same app/window/element. A stale object becomes `unavailable/staleContext`; Pulse must never act on the nearest same-named replacement.

## V1 object classes

Minimum object taxonomy:

- `TextSelection`
- `SelectedFile`
- `FileReference`
- `ImageFile`
- `AudioFile`
- `VideoFile`
- `URLObject`
- `UIElementObject`
- `FocusedElementObject`
- `WindowObject`
- `ApplicationObject`
- `ClipboardText`
- `CodeSnippet`
- `ErrorLog`
- `JSONText`
- `ShellText` (inspection only in V1 unless explicitly generated by trusted Pulse code)
- `RepositoryObject`
- `GitReferenceObject`
- `ResultObject`
- `MachineObject`
- `ProjectObject` where resolvable without invasive scanning

Classification is compositional. A selected `.png` in Finder may be both `SelectedFile` and `ImageFile`; application logic should resolve the most specific applicable type while preserving ancestry/provenance.

## UIElementObject

V1 must support Accessibility elements under the pointer.

Capture safe metadata where available:

- role/subrole;
- accessible title/label;
- enabled/disabled;
- value only when safe and non-secure;
- owning application/window;
- screen frame;
- available AX actions;
- whether the element appears destructive/ambiguous.

Generic activation is not automatically safe. If an element can plausibly trigger deletion, irreversible submission, purchase, send, or unknown consequential behavior, V1 must not expose an executable activation Reflex simply because AX reports `AXPress`.

## Targets

Targets are typed, not freeform strings.

V1 examples:

- `MacBookTarget`
- `BigMacTarget`
- `OllamaTarget`
- application target
- project/repository target
- destination/pin/Spool target

Provider/model Targets may exist, but user-facing Reflex names remain task-oriented.

## Results

A Result Object includes:

- type;
- user-display summary;
- payload/reference;
- source Reflex ID;
- executor ID;
- Target ID if any;
- execution run ID;
- persistence state: transient | pinned | project-kept;
- Witness receipt reference.

A Result can be re-pulsed without re-running its producer.

## Durable pins

Persistence policy:

- file: security-scoped bookmark/reference when needed;
- URL: normalized URL reference;
- repository/project: stable path + identity metadata;
- UI element: generally cannot be durably pinned as a live object; persist a recipe/locator only if explicitly supported and validated;
- text/result: persist content only because the user explicitly pinned it and no external durable reference exists.

Never copy large files into Pulse storage merely because they were pinned.

## Stable directional layouts

Layout stability attaches to object-class layout schema versions.

Example concept:

```text
layoutID: error-log.v1
slots:
  N: explain
  NE: search-evidence
  E: diagnose
  SE: send-agent
  S: witness
  SW: find-source
  W: repair-packet
  NW: regression-test
```

This is an example, not a frozen V1 mapping.

Before a layout is frozen, usability tuning may move slots. After freeze, changes require an explicit migration/version decision and must not silently retrain user motor memory.
